# ChatGPT Response Sound

**中文** | [English](README_EN.md)

> [!IMPORTANT]
> ## 项目状态：暂停维护
>
> 这个项目最初用于解决 ChatGPT 多标签页工作时缺少可靠回复完成提示音的问题。
>
> 在实际开发和长期测试过程中，我发现 ChatGPT Web 的完成通知存在比较复杂的跨标签页行为：
>
> - 同一个回复完成事件可能在多个其他 ChatGPT 标签页中出现通知；
> - 为避免重复提示，需要进行跨标签页仲裁；
> - 即使完成事件能够去重，声音也不一定能可靠地从真正完成回复的标签页播放；
> - 多标签页下持续监听页面 DOM 的性能影响仍未得到充分验证。
>
> 因此，我目前已经停止将本扩展作为日常使用方案继续开发。
>
> ### 推荐替代方案
>
> 我目前使用 [Reply Chime](https://addons.mozilla.org/firefox/addon/reply-chime/)。
>
> 在开发者回复用户反馈并更新版本后，我重新进行了真实的多标签 ChatGPT 工作流测试，目前它已经能够满足我的回复完成提示需求。
>
> 本仓库继续保留，主要作为一次关于 ChatGPT Web 完成通知、多标签页行为和 Firefox 扩展实现的实验记录。

一个极简的 Firefox 扩展：当 ChatGPT Web 显示后台回复完成通知时，播放一次简短提示音。

## 为什么做这个扩展

同时运行多个 ChatGPT 标签页时，后台回复完成后的页面通知很容易被错过。这个扩展只做一件事：**当 ChatGPT 自己显示一条新的后台完成通知时，响一下。**

## 设计原则

- 目前仅支持 Firefox。
- 仅运行于 `https://chatgpt.com/*`。
- 不需要账号、后端服务或网络请求。
- 不包含统计、跟踪或遥测。
- 不提供弹窗、设置页、历史记录或通知中心。
- 直接监听 ChatGPT Web 自己产生的后台回复完成通知。
- 同一完成事件即使被 ChatGPT 同步到多个标签页，整个 Firefox 实例也只播放一次声音。
- 优先用通知中的 conversation URL 定位回复完成页；没有可用 URL 时，再用通知文本匹配各 ChatGPT 标签页标题；仍无法定位才回退到最先报告该事件的标签页。
- 不推断普通前台回复的完成状态；前台可见回复完成但没有产生完成通知时，不会播放声音。
- 如果 ChatGPT 改版导致无法识别完成通知，扩展会保持静默，而不是猜测回复状态。

## 临时安装与测试

1. Clone 或下载本仓库。
2. 在 Firefox 中打开 `about:debugging#/runtime/this-firefox`。
3. 点击 **加载临时附加组件…**。
4. 选择仓库中的 `manifest.json`。
5. 重新加载已经打开的 `chatgpt.com` 标签页。

Firefox 重启后会移除临时加载的扩展。本仓库目前处于暂停维护状态，暂不计划正式打包和签名。

## 使用方式

正常使用 ChatGPT 即可。当 ChatGPT Web 产生后台回复完成通知时，扩展会在整个 Firefox 实例中为同一完成事件只播放一次短提示音。

如果通知包含可识别的 conversation 链接，声音会优先从对应的回复完成标签页播放；若没有链接，则尝试用通知文本匹配标签页标题，因此 Firefox 的音频指示会尽量落在正确标签页。两种方式都无法定位时，才从最先报告该事件的标签页播放。不同完成事件仍会各自提醒。普通前台可见回复如果没有产生这类通知，则不会响。

## 已知限制

本项目依赖 ChatGPT Web 当前的页面通知实现。OpenAI 可能随时调整相关 UI；如果通知结构发生变化，扩展可能需要更新。

设计上优先选择“失效时不响”，而不是为了保持响铃而降低完成判断的准确性。

## 隐私

所有逻辑都在浏览器本地运行。扩展不会收集、上传或保存对话内容，也不会发送网络请求。
